# Personal Knowledge · AI 对话知识归档

一个以 AI 对话内容为主要来源的知识资料库。

这里保存值得反复阅读的解释、推导、例子和探索过程。归档的目的，是让一次有价值的讨论变成方便阅读、搜索、回顾和继续学习的文档，而不是把 AI 回答包装成我的个人总结。

## 与个人博客的分工

- **个人博客**：以我自己的理解、思考和表达为主体。写作过程可以借助 AI 做格式调整、语言修正、事实核对，但文章应体现我本人对内容的消化和表达，可作为费曼学习法的实践。
- **本仓库（AI 归档）**：以 AI 对话及其整理结果为主体。内容可能尚未经过我独立理解、验证或实践，不应默认代表我的观点、经验或已经掌握的知识。

两者都可以面向自己或其他读者；划分依据是**内容如何形成**，不是“我是否已经掌握”的绝对判断。以后个人网站可以为本知识库提供独立入口，两类文章也可以互相引用。

## 归档原则

1. **忠实于讨论**：保留重要问题、解释、追问、推理和边界；可以删掉寒暄与重复，但不能为了文章完整而杜撰经历、实验或结论。
2. **可读性优先**：不原封不动堆砌聊天记录。按主题组织成清楚、连贯、可独立阅读的 Markdown 资料。
3. **方便检索**：标题具体、主题清晰；独立主题可拆分，持续讨论同一主题时优先更新已有文档。
4. **内容身份明确**：归档通常由 AI 整理，不冒充用户独立写作或已验证的个人心得；未经核验的信息要说明不确定性。
5. **保留学习空间**：归档不要求用户已经理解，也不要求每份资料都进一步写成个人博客。
6. **框架无关**：知识正文尽量使用标准 Markdown；交互演示可以另存独立 HTML/JS 文件。

## 仓库隐私与发布

计划将本仓库从 Public 改为 Private，但**当前仍是 Public**。在实际切换和核对发布配置前，所有提交都按公开内容审查：不得提交密钥、凭证、企业内部信息、敏感个人信息或未获授权的第三方内容。改为 Private 也不会自动使已发布的网站私有，更不能撤回已被获取的历史内容。

仓库访问权限和网站阅读权限是两件事：今后即使源仓库私有，也可以另行决定是否公开发布网站。现阶段不假设网站已经私有。

## 如何归档

在 AI 对话中提出“归档到 personal-knowledge”，并说明主题与期望保留的范围。归档前查找已有文章；按讨论内容决定更新还是新建，必要时先商量拆分范围。整理时以内容准确和可读为优先，不强制套用个人博客文风。

详细规范见 [AGENTS.md](AGENTS.md)；[WRITING_STYLE.md](WRITING_STYLE.md) 主要供个人作者风格的写作任务参考，而非 AI 归档默认规则。
